# Размещение на VPS real-clients.ru

Подготовленные файлы рассчитаны на Linux с systemd, Nginx и Python 3.12. Они не заменяют проверку существующих сервисов и свободных портов. Секретов в этих файлах нет.

Расположение:

- `/opt/lectory/releases/REVISION/`: исходники, `frontend/dist/`, собственная `.venv` релиза.
- `/opt/lectory/current`: ссылка на текущий релиз.
- `/var/lib/lectory`: постоянная SQLite, видео и модели, владелец `lectory`.
- `/etc/lectory/lectory.env`: приватные параметры, `root:root`, права `600`.
- API слушает только `127.0.0.1:8102`. Наружу его публикует Nginx с HTTPS.

Порядок установки после инвентаризации сервера:

1. Создать системного пользователя `lectory` и каталоги приложения. Сохранить резервные копии конфигурации, если этот домен уже обслуживается Nginx.
2. Разместить исходники и собранный `frontend/dist/` в отдельном каталоге релиза. Установить зависимости из `requirements.lock` в `.venv` релиза.
3. Создать настоящий `lectory.env` вне репозитория. Передать API-ключ на сервер по SSH, не через аргументы команд или журналы.
4. От имени `lectory` с теми же переменными выполнить `python -m backend.cli download-models`, затем отдельно создать администратора или явно загрузить демо. Учётные данные демо не публиковать.
5. Установить два `.service`, выполнить `systemctl daemon-reload`, включить сервисы. Проверить `curl http://127.0.0.1:8102/api/health` до переключения домена.
6. Проверить A/AAAA домена. Установить отдельный virtual host из `nginx-http.conf`, выполнить `nginx -t` и перезагрузить Nginx.
7. Выпустить TLS-сертификат для `real-clients.ru`, включить HTTP → HTTPS и автоматическое продление средствами Certbot.
8. Проверить через публичный адрес вход, защищённую cookie, плеер, поиск, генерацию ответа, загрузку видео и состояния worker. Убедиться, что `.env`, БД и исходники недоступны через HTTP.

Операционные команды:

```sh
systemctl status lectory-api lectory-worker
journalctl -u lectory-api -u lectory-worker --since '15 minutes ago'
nginx -t
certbot renew --dry-run
```

Перед обновлением сохранить согласованную копию SQLite через `.backup` и медиаданные. Для возврата предыдущего кода переключить `current` на предыдущий релиз и перезапустить сервисы. Данные не удаляются и не копируются из демонстрационной БД при обновлениях.

Этот каталог содержит конфигурацию и процедуру. Факт успешного развёртывания подтверждается отдельной проверкой публичного HTTPS-адреса.
